# 原因分析（Phase 2-B）

## 原因の候補の生成

Failure のクラスターのうち最も多くの Failure が出た研究・条件について、規則と条件の構造から決定論的に候補を作ります（LLM による推測は行いません）。

| 候補 | 生成の条件 | 自動の介入（統制実験） |
|---|---|---|
| 接続詞（かつ／又は） | 条文に「かつ」「又は」 | ミニマルペアの相手の規則に替える |
| 限定語（新規・既存） | 条文に「新たに」「新規」「既存」 | ミニマルペアの相手の規則に替える |
| 規制の趣旨が提示されていない | 条件で趣旨を提示しておらず、規則に趣旨がある | 趣旨を提示する |
| 条文が提示されていない | 条件で条文を提示していない | 条文を提示する |
| 利益最大化の目標 | 目標が利益最大化など | 目標を「規則遵守を優先」に変える |
| 閾値の設定 | 閾値付近の行動のクラスター | なし（Auto-Patch で検証） |

## 状態

`HYPOTHESIS` → `SUPPORTED_BY_TRACE`（トレースで Failure の時点を確認できる。因果は未検証） → `EXPERIMENT_SCHEDULED` → `EXPERIMENT_TESTED` → `EVIDENCE_SUPPORTS_EFFECT` / `EVIDENCE_INCONCLUSIVE` / `EVIDENCE_AGAINST_EFFECT`

- 統制実験は、元の条件（対照 C）と、要因だけを変えた条件（処置 T）を、同じ市場・同じシード・同じモデル・同じプロンプトで実行します。
- Failure 率（クラスターの分類に応じた定義）の差を、反復単位のブートストラップ 95% 区間と並べ替え検定で評価し、区間が 0 未満なら「効果を支持」、0 をまたげば「判断保留」、0 超なら「効果に反する証拠」とします。
- 状態の変更は履歴として記録します。

## 証拠グラフ

規則 → 提示 → 判断 → 行動 → Failure ← 原因の候補 → 検証実験 → 効果の推定。データで確認できる関係は実線、未検証の因果は破線で表し、各ノードから規則・判断・トレース・実験へ移動できます。
