# 実証研究プラットフォーム（規則解釈AI研究コンソール）

条文の文言だけを変えた「条文ミニマルペア」を作り、同じ市場・同じシードで AI エージェントを動かして、
行動・規則エンジンの判定・説明を分けて記録し、統計的に比較してエクスポートするための機能です。

> **参考にした論文について**: 意思決定ログを 4 要素（表明された説明・提案された行動・実行時の判定・監視の証拠）に分けて記録する構造は、
> 実装指示書に記載された ReguSim の説明を参考にしています。開発環境から論文本文（arXiv）にアクセスできなかったため、
> 論文固有の詳細（ReguBench の具体的な構成など）は実装に使っていません。論文に記載された実証結果をアプリの結果として表示することはありません。

## 実装状況

「実装済み」は、自動テストまたはブラウザでの確認（`e2e/study-flow.mjs`）で動作を確認したものだけです。

### 実装済み

| 区分 | 内容 |
|---|---|
| 規則 | JSON の規則 DSL（変数・演算子はホワイトリスト、`eval` なし、深さ・要素数の上限）。保存のたびに新しい版を追加し、既存の版は変更しない。判定ロジックのハッシュを記録 |
| 規則 | 条文ミニマルペアの雛形 2 種（見せ玉「かつ／又は」、空売り価格規制「新規／すべて」）。例示条文であり実在の法令ではない |
| 規則 | ミニマルペアの文字単位の差分表示、判定ロジックの比較、研究者による差分分類・等価性の確認（自動では確定しない） |
| プロンプト | 版管理（`{{名前}}` の差し込みのみ。必須の差し込み位置を検証） |
| 研究デザイン | 研究課題・仮説・変数・分析計画（事前登録）、最大 8 条件、主要比較、反復・シード、市場条件 |
| 実行 | 開始時に設定（デザイン・規則の版・プロンプト・モデル設定・コードのバージョン）を凍結し SHA-256 を記録。APIキーは含めない |
| 実行 | セッション = 条件 × 反復。同じ反復番号は全条件で同じシード（同じ価格系列）。実行順はハッシュでばらす |
| 実行 | `FOR UPDATE SKIP LOCKED` とリースによる排他的なセッション取得、ログ保存と完了記録を同一トランザクションで実施（二重保存なし）、一時停止・再開・停止、致命的なエラーでの自動一時停止 |
| 市場 | 外生価格＋単純約定（`exogenous_simple`）。金額は銭単位の整数。未約定の指値、取消、空売り |
| 判定 | 決定論的な規則エンジン。AI の適法性の主張は判定に渡さない。拒否された注文は約定せず、「規制の突破」には数えない |
| ログ | A. 実験条件 / B. 表明された説明 / C. 提案された行動 / D. 規則エンジンの判定 / E. 監視AIの評価（現状は常に未実施）を分けて保存・表示 |
| モック | API キー不要の決定論的モックエージェント。結果・画面・ファイル名に「モックデータ」を明示 |
| 統計 | 比率と Wilson 95% 区間、平均・中央値・SD、反復単位の対応のあるブートストラップ、符号反転の並べ替え検定、Holm 補正、Cohen h、オッズ比、χ² 検定・Fisher の正確検定（独立を仮定した参考値として明示） |
| 図表 | 条件別の比率の棒グラフ（95% 区間、凡例、ホバー表示）、SVG / PNG 保存 |
| 出力 | レポート（Markdown、方法・限界・法的免責を含む）、意思決定ログ CSV、セッション CSV、集計 JSON、凍結設定 JSON（CSV は数式インジェクション対策済み） |
| ログイン | アプリのログイン画面（/login）でパスワードを入力。署名付きのセッション Cookie（HttpOnly・12時間）を発行し、ブラウザの認証ダイアログは使わない。パスワードは従来どおり環境変数 `BASIC_AUTH_PASSWORD`。スクリプトからは Authorization ヘッダーでも利用可 |
| セキュリティ | CSRF 対策（Fetch Metadata / Origin、JSON の Content-Type 必須）、パスワード誤りの連続による接続元の一時拒否、監査ログ（規則・ペア・研究の操作） |

## 研究者向けの使い方

1. **規則・条文** → 雛形の「この雛形で条文A/Bを作成」。または「新しい規則」で条文と判定ロジックを書く。
2. 作成されたミニマルペアの画面で差分を確認し、「差分の分類」と「確認結果」を保存する。
3. 「このペアで研究を作成」→ 仮説・分析計画・反復数などを入力して下書き保存。
   - エージェントは、まず「モック」で流れを確認し、本番の研究では「AIモデル」（設定 → モデル割り当ての「取引エージェント」）を選ぶ。
4. 研究の画面で「設定を凍結して開始」。進捗は自動で更新される。
5. 結果表・グラフ・比較表を確認し、意思決定ログの行を開いて 4 要素を確認する。
6. 「エクスポート」からレポートやデータを保存する。

### 指標の定義

- **規則違反率** = 規則に基づき拒否された試行 ÷ 発注・取消の試行。取引所の基本チェック（現金不足など）のみによる拒否は含めない。
- **拒否率** = 拒否された試行 ÷ 試行（基本チェックを含む）。
- **趣旨逸脱率** = 受理された注文のうち、規則で事前定義した「趣旨逸脱の基準」に該当した割合。
- **説明と判定の不一致** = 拒否された注文のうち、AI が「適法」と自己評価していた割合。

## 再現手順

研究の「凍結設定（JSON）」には、デザイン・規則の各版（条文と判定ロジック）・プロンプト・モデル設定・コードのバージョン（Vercel のコミット SHA）が含まれます。

1. `frozenHash` は `frozenConfig` から運用設定（タイムアウト等）と凍結時刻を除いた内容の SHA-256（キー順を正規化した JSON）です。
2. 同じコミットのアプリで、同じ規則の版・プロンプト・デザインの研究を作ると、同じ市場（価格系列）が生成されます。
3. モックエージェントの結果は完全に再現されます。AI モデルの出力は確率的なため、同じ設定でも一致は保証されません。

## 環境変数

既存の変数（`BASIC_AUTH_PASSWORD`、`DATABASE_URL`、`API_KEY_ENCRYPTION_KEY`、`CRON_SECRET`）から追加はありません。
データベースのテーブルは起動時に `CREATE TABLE IF NOT EXISTS` で追加され、既存のテーブル・データは変更・削除しません。

## 検証方法（ローカル）

```bash
npx tsc --noEmit && npx eslint app components lib proxy.ts e2e
npx vitest run                                     # 組み込み Postgres（PGlite）
TEST_DATABASE_URL=postgresql://... npx vitest run  # 実 PostgreSQL
npx next build
# ローカルでサーバーを起動してブラウザで一連の流れを確認（本番には実行しない）
BASIC_AUTH_PASSWORD=... RESEARCH_DATA_DIR=/tmp/e2e npx next start -p 3100
E2E_BASE_URL=http://127.0.0.1:3100 E2E_PASSWORD=... node e2e/study-flow.mjs
```

## 本番反映時の注意

- 反映すると新しいテーブル（`rc_rules` など 6 つ）が自動で追加されます。既存データは削除されません。
- AI モデルでの研究は「条件数 × 反復数 × ステップ数」回の API 呼び出しが発生します（開始時に確認ダイアログを表示）。予算は設定 → 費用管理で上限を設定してください。
- 長い研究は Vercel の関数実行時間で分割して処理されます。`CRON_SECRET` が未設定の場合、処理の引き継ぎは画面を開いている間と 1 日 1 回の Cron に限られます。
- 規則エンジンの判定・レポートは研究用であり、法的効果や法的助言ではありません。
