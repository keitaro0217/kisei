# Failure-to-Test パイプライン（Phase 2-A）

```text
研究の実行 → 逸脱の疑いを検出 → Failure として登録（判断ごとに1件） → 特徴で分類（クラスター）
→ 再現条件を抽出 → テストケースの候補 → 研究者の確認（期待する趣旨の判定を人が確定） → 回帰テストのデータセット
```

## 検出

| 分類 | 条件 | 検出した評価器 |
|---|---|---|
| 形式違反 | 規則に基づく拒否 | engine |
| 趣旨逸脱の疑い | 事前基準に該当、Judge（根拠のある判定）が逸脱の疑い、または人が逸脱と評価 | criteria / judge / human |
| 閾値付近の行動 | 受理された行動の閾値までの相対距離が 10% 以内 | engine |

人が「趣旨に適合」と評価した判断は、趣旨逸脱・閾値付近としては登録しません。同じ判断は再検出しても重複して登録されません（一意制約）。

## 分類（クラスター）

分類・規則・コード・行動の種類・数量帯（小口・中口・大口）・市場の局面（上昇・下落・横ばい）・保有（買い持ち・なし・売り持ち）からハッシュを作り、同じハッシュを同じクラスターとします（決定論的）。複数の研究で見つかったか、確認済みの Failure があるクラスターを「既知」とします。重大度の初期値は機械的（形式違反 = 高、趣旨逸脱 = 中、閾値付近 = 低、人が逸脱と確認 = 高）で、人が変更できます。

## テストケース

- クラスターの代表例（確認済みを優先し、異なる研究・条件から）を、クラスターごとの上限つきで候補にします。同じ元からは重複して作りません。
- 再現条件: 判断の時点の取引所の状態（価格・直前約定・現金・保有・未約定・取消回数・注文番号）、規則の版、エージェントの設定、行動、期待する形式判定。
- 期待する趣旨の判定は AI の推測では確定せず、研究者が選んで承認します（承認には必須）。
- 正常な行動のケース（誤拒否の検証用）を、受理され指摘のない判断から無作為に作れます。

## 実装状況

| 項目 | 状態 |
|---|---|
| 検出・重複排除・分類・新規／既知・重大度・テストケース化・人の承認 | COMPLETE |
| 埋め込みモデルによる類似度の分類 | NOT IMPLEMENTED（決定論的な特徴量のみ） |
| 時系列パターン（複数ステップにわたる行動）の分類 | NOT IMPLEMENTED |
| ストレスケースのデータセット | NOT IMPLEMENTED |
