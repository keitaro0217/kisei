# システム構成

**Trace → Detect → Explain → Patch → Verify → Monitor** を1つの製品として扱う構成です。中核のドメインモデル（規則・研究・セッション・判断・トレース・Failure・仮説・修正案・回帰テスト）は業界に依存しない形にし、金融固有の部分（合成市場・取引所・規則の変数）は差し替え可能な層に置いています。

```text
Next.js（App Router・React 19）
  app/research/**           画面（クライアントコンポーネント）
  app/api/research/**       API（withAuth で権限を再検証）
  app/api/monitor/events    監視イベントの取り込み（接続元トークン）
        │
lib/server/research
  study/        研究の作成・凍結・実行（セッション単位・リース・排他）、統計、回帰分析、出力
  trace/        Span の記録（Tracer）、OTLP 形式への変換
  eval/         LLM Judge・モック Judge・多層評価・人の評価・一致率
  failure/      Failure の検出・分類・テストケース化、原因の候補・統制実験・証拠グラフ
  patch/        修正案の生成・承認の流れ・実験用の規則、回帰テスト・ゲート・パレート
  poc/          PoC の価値測定・レポート
  monitor/      外部イベントの取り込み・一次判定・警告（試験版）
  sim/          合成市場（外生価格）・取引所（単純約定）  ← 金融固有
lib/server/rules/dsl.ts     規則 DSL（ホワイトリスト・決定論的評価・閾値付近の度合い） ← 業界非依存
lib/server/llm              5 プロバイダーのアダプター（既存）
lib/server/storage          PostgreSQL / PGlite への保存
        │
PostgreSQL（Neon） / PGlite（ローカル・テスト）
```

## 設計原則と実装状況

| 原則 | 実装 |
|---|---|
| フロントエンドと処理の分離 | 画面は API だけを呼び、評価・統計・判定はサーバーのモジュールに置く |
| 既存の LLM クライアントの再利用 | 取引エージェント・Judge とも `invokeModel`（予算・再試行・使用量の記録）を使う |
| 長時間の処理はジョブ | 研究のセッション・Judge の評価はワーカー（`runPendingWork`）がスライス単位で処理。リース・冪等（判断の主キー・ON CONFLICT）・一時停止・再開 |
| 実験条件は不変 | 開始時に凍結し SHA-256 を記録。規則・プロンプトは版で管理し、既存の版は変更しない |
| 分析結果にデータの版 | 回帰テストに判定エンジンの版、評価にプロンプトの版とハッシュ、マニフェストにデータの指紋 |
| 本番 API キーをテストに使わない | テストはモックの LLM サーバーとモックエージェントのみ（実 API のテストは明示的に有効化した場合だけ） |

## ワーカー

既存の Vercel 向けの分割実行（`after()` → スライス → `/api/research/worker` で引き継ぎ、Cron 1日1回）をそのまま使い、研究のセッションと Judge の評価を追加しました。

| 要件 | 状態 |
|---|---|
| ジョブ ID・進捗・再試行・リース・冪等・一時停止・予算 | COMPLETE（研究のセッション・評価の実行） |
| 同時実行の上限 | PARTIAL（研究ごとの並列数とプロバイダーごとの同時接続数。全体の上限はない） |
| 重複した LLM 呼び出しと重複保存の区別 | PARTIAL（保存は主キーで重複しない。リースの期限切れ時に同じ判断を再実行した LLM 呼び出しは使用量に記録されるが、区別して集計する画面はない） |
| 専用ワーカーへの切り替えの抽象化 | NOT IMPLEMENTED |

## LangSmith との連携

kisei 内部のトレースモデルを中核にし、OpenTelemetry（OTLP/JSON）形式で書き出せるようにしました（`format=otlp`）。LangSmith などへの自動転送は実装していません（NOT IMPLEMENTED）。外部転送を加える場合は、明示的な設定で有効化し、プロバイダーの API キーとは別に鍵を管理してください。
