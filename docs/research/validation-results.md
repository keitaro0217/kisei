# 評価器の検証結果

## 結論

**実データ（実 LLM の行動・外部の専門家ラベル）での評価器の検証は、まだ行っていません。** 評価器の精度は「未測定」です。

以下は、パイプラインが正しく動くことを確かめるための**合成のテストデータ**での結果です。研究結果や評価器の精度の主張には使えません。

## 合成テストでの結果

### 条件

| 項目 | 内容 |
|---|---|
| 行動 | モックのエージェント（決定論的）。3条件 × 6反復 × 20ステップ（`tests/phase2.test.ts`） |
| 規則 | 合成の規則 SPOOF-AND / SPOOF-OR / POS-LIMIT-EX（実在の法令ではない） |
| Judge | モックの Judge（規則ベース）。通常の順序と、証拠を逆順にした2つの評価の実行 |
| ラベル | 規則の定義から機械的に作った「正解」120件（評価者A）。評価者B は一部（8件）で判断を変えたもの。用途は `evaluation_test` |
| DB | PostgreSQL 16（ローカル） |

その他の結果:

- 正解: 112件。評価者の間で割れた8件は除外しました。
- 評価者間の一致: 一致率 0.933、κ = 0.671。
- 証拠の順序の影響（モック Judge どうし）: 一致率 1.0。

### 読み方

- **事前基準・複合評価が 1.0 なのは、正解ラベルを評価器と同じ規則の定義から作ったため（循環）です。** 評価器が正しいことの証拠ではありません。ラベルの登録、混同行列、未測定の扱い、除外、警告、区間の計算が正しく動くことを確かめたものです。
- 規則エンジンが「趣旨逸脱」を見逃すのは仕様です（形式だけを評価する）。2つの評価軸を分けている理由を示しています。
- どの評価器にも「件数が少ない」「クラスの件数に偏り」の警告が出ました。少数クラス（趣旨逸脱 3件）の区間は非常に広いです。
- モックの Judge は証拠の順序に影響されません（規則ベースのため）。実 LLM の Judge で同じ検証をすることが次の課題です。
