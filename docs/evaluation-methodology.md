# 多層評価（Phase 1-B）

判断ごとに、独立した複数の観点の結果を別々に保持します。単一のリスクスコアにはまとめません。

| 層 | 評価器 | 指標 |
|---|---|---|
| 1. 形式適合 | 規則エンジン（決定論的・コード） | 規則違反・取引所の基本チェック・違反コード |
| 2. 規制趣旨 | 事前定義の趣旨逸脱の基準（コード）・LLM Judge・人の評価 | 趣旨逸脱の疑い・判断不能 |
| 3. 経済・業務 | 研究データから算出 | 損益・対照群との差（超過損益）・閾値付近の集中度・誤拒否率（人の評価が必要） |
| 4. 証拠の質 | 研究データ・Judge の出力 | 引用規則の実在・説明の有無・説明と判定の不一致・Judge の不正な引用 |
| 5. 評価器の信頼性 | 人の評価（多数決）を正解とする | 一致率・Cohen の κ・Precision / Recall / F1・評価不能率・Judge 間・評価者間の一致 |

流動性・スプレッドへの影響は、外生価格の市場では測定できないため「測定対象外」と表示します。

## 最終表示

1. 行動を解釈できない → 判定失敗
2. 規則違反 → 形式違反（趣旨の評価は別に保持）
3. 人の評価がある → 多数決（同数なら人による確認待ち）
4. 事前基準と（根拠のある）Judge が一致 → 形式適合・趣旨適合／趣旨逸脱の疑い
5. 不一致または「判断できない」→ 人による確認待ち
6. Judge を実行したが根拠のある判定が得られない → 証拠不足

## LLM Judge

- プロンプトは版（`intent-judge-v1`）とハッシュで管理し、評価の実行に記録します。
- 証拠に ID（E1…）を付けて渡し、Judge にはその ID だけを引用させます。存在しない ID の引用は記録して表示します。
- 出力は JSON スキーマで検証し、不正な項目はエラーとして記録します（推測で補いません）。
- 証拠の本文（条文・エージェントの説明）はデータとして扱い、その中の指示に従わないよう指示し、区切りタグを取り除きます（プロンプトインジェクション対策）。
- Judge の自己申告の不確実性は、統計的に校正された確率として扱いません。
- モック Judge（規則ベース、API キー不要）は評価の流れの検証と比較基準のためのもので、AI の判断ではありません。
- 標本は指摘のある判断を優先し、残りを無作為に選びます（シードで再現可能）。

## 人の評価

評価者名（共有ログインのため名前で区別）・趣旨の評価・形式判定の正誤・理由・Judge の修正（理由必須）を保存し、修正前の内容は履歴に残します。ゴールドデータとして JSON で出力できます。
